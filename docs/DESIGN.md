# Pizzic 设计决策记录

本文档记录 Pizzic v0.1 的关键设计决策与理由，作为后续演进的基准。

## 1. 模块格式：闭合的 XML 语义标签（ADR-003）

```markdown
<pizzic-module name="codegraph">
（正文）
</pizzic-module>
```

- `name` 必填：首尾为字母数字/连字符/下划线，**内部允许空格**（支持
  `"rtk-instructions v1"` 这类版本化命名），不含引号/尖括号（标签结构不可被注入，
  生成端对非法名直接抛错）；闭合标签带元素名，配对自校验。
- 停用态以属性表达：`<pizzic-module name="x" enabled="false">`（缺省 `enabled="true"`，
  属性顺序无关；接受自闭合 `<pizzic-module name="x"/>` 作为空模块，生成端不产出该形态）。
- **行首约束**：标签必须独占行首（允许前置空白），行内出现的标签视为普通文本——
  防止讲解性文字误配对。
- **围栏排除**：fenced code block（``` 与 ~~~）内的标签不参与解析。
- **不可信 XML 载体拒绝**：文件含 `<!DOCTYPE`/`<!ENTITY` 时整体不解析模块结构。
  解析器是扫描式的，不构建实体表、不启用外部实体，但拒绝承接此类内容是纵深防御。
- 模块扁平、不允许嵌套：未闭合时遇到新的开标签，放弃上一块从此处重开（容错）；
  游离的闭合标签视为普通文本；未闭合的开标签延伸到文末。
- 模块**展示名**优先取正文第一个 Markdown 标题，否则用模块名本身。
- **兼容策略——双读单写**：v0.1 的注释标签（`<!-- Pizzic:begin:name [disabled] -->` /
  `<!-- Pizzic:end -->`）仍可读取（标记为 legacy 块）；写入一律产出 XML 语义标签，
  对旧块的任何编辑（停用/启用/重命名）都会把开/闭标签整体升级为新格式（closeUpgradeEdits）。

相比 v0.1 注释标签的动机：闭合标签自描述配对（旧 end 标签不带名字，靠顺序配对脆弱）、
状态是真属性模型而非注释内魔法词、形态可被标准 XML 工具链处理。

## 2. 停用语义：空壳 + 本地存档（ADR-001，已被 ADR-004 修订）

> **修订说明**：空壳方案已被 ADR-004（整块移除 + 存档即停用）替代，本节保留作为决策痕迹。
> 修订动机与配套设计见第 9 节。

**决策**：停用模块时，把正文从目标文件中移除并写入 Pizzic 的状态存档
（`%APPDATA%/app.pizzic.workbench/state.json`，按 目标文件路径 + 模块名 键控），
文件中留下 `enabled="false"` 的空壳（壳内保留一个换行，维持闭合标签行首）；启用时从存档恢复。

**备选方案与否决理由**：

- *把停用正文注释留在文件里* — 模块正文本身常含 HTML 注释（如
  `<!-- CODEGRAPH_START -->`），嵌套 HTML 注释会破坏结构，且 Agent 仍会读到停用内容；
- *整段直接删除不留壳* — 模块在文件中的位置与身份信息丢失，重新启用无处安放，
  面板也无法展示「此处有一个已停用模块」。

空壳方案让文件自身保持自描述（模块列表可从文件恢复），存档只负责正文。

**已知权衡**：停用内容的生命线依赖 Pizzic 的 state.json；若用户绕过 Pizzic 手工删除
空壳或清理存档目录，该模块正文不可恢复。面板对「空壳存在但无存档」的模块给出
「无存档」警示。

## 3. 职责划分：解析在前端，IO 在后端

- `src/lib/document.ts`：纯函数领域核心 —— 标签解析、偏移量操作（停用/启用/重命名/
  删除/包裹/注入）。偏移量与 CodeMirror 的 UTF-16 语义一致，操作直接映射为
  CM dispatch，无需二次对齐。以 `scripts/dev-check.ts` 自检（Node 原生跑 TS）。
- `src-tauri/`：只做三件事 —— 注册表文件 IO、`notify` 监听、停用存档。

**理由**：模块操作全部围绕编辑器偏移量发生，放在前端避免高频 IPC；解析器保持纯函数
便于独立验证；Rust 保持薄壳，安全面（路径白名单）收敛。

## 4. 安全：路径白名单

所有 `read_file` / `write_file` / 存档命令只接受 `targets.rs` 注册表中的路径
（大小写不敏感比对）。Webview 即使被注入也无法读取/写入任意文件。
写文件采用临时文件 + 原子替换（`tempfile::persist`），失败时回退直接写。

符号链接引入后该不变量继续成立（第 11 节）：`write_file` 一律拒绝符号链接路径
（否则会穿透链接改到目标）；符号链接只在其**唯一安全目标**（私有共享指令文件）
时读取内容，指向其他文件时只呈现警告与修复动作，不读取目标内容。

## 5. 监听：目录级 watch + mtime 回声抑制

- 监听主目录与**每个候选文件的父目录**（去重后约 30 个，全部非递归）：主目录
  用于感知新增的一级目录，父目录用于感知文件本身的新建/修改/删除。早期版本只
  监听 `~` 与 `~/.config`，而所有指令文件都在子目录中，非递归监听收不到子目录内
  的变更（Windows 实测 0 事件）——该缺陷在符号链接支持中一并修复。
- 每 4 秒补挂一次尚未监听的目录（首次使用某个 Agent 时目录可能才被创建）。
- 300ms 窗口聚合事件，仅对注册表内的路径发 `pizzic:file-changed`。文件被删除、
  或变成悬空链接时同样发事件（`symlink_metadata` 判定），前端据此更新侧栏分组
  与编辑器空态。
- Pizzic 自写后记录 `(路径 → mtime)`，命中则跳过发射 —— 抑制自我回声。
  残余竞态（发射恰好在记录前）由前端兜底：重载文本与编辑器一致时不改状态。
- 前端脏态处理：无未保存修改 → 自动重载；有 → 横幅让用户选择（放弃 / 覆盖）。
  文件被外部换成符号链接时只提供「放弃修改并重新加载」，绝不提供覆盖写。

## 6. 视觉语言：Ethereal Glass

深空底（`#07080B`）+ 双光斑（紫 `#7C5CFF` / 青 `#2DD4BF`，固定层 blur）+ 胶片噪点；
所有面板采用「机壳嵌套」：外壳玻璃卡（`ring-white/7`、内高光）托住更深的内芯，
同心圆角；字体 Geist Sans / Geist Mono；图标 Phosphor Light；
动效统一 `cubic-bezier(0.32, 0.72, 0, 1)`，入场为 rise（上移 + 模糊消散），
面板行错峰延迟。模块用六色相（紫/青/金/玫/蓝/草，按名字哈希取色）贯穿编辑器
装饰与面板圆点。

## 8. 换行符：编辑器内统一 LF，保存按文件模式还原（ADR-002）

CodeMirror 6 的 Text 存储层不保留 `\r`：实测无论 create 还是 dispatch、无论是否设置
`EditorState.lineSeparator` facet，`\r\n` 一律被归一化为 `\n`
（`scripts/cm-eol-probe.mjs` 可复现）。因此 CRLF 文件加载后 `doc.toString()` 与磁盘
文本必然不一致 → 误报「未保存」，且直接保存会把文件**静默改写为 LF**。
（第一版曾尝试用 lineSeparator facet 保真，已被上述实证否决。）

**决策（VS Code 式模型）**：

- 编辑器内部永远是 LF 语义（顺势接受 CM 的归一化，不再与存储层对抗）；
- 换行模式作为**文件属性**单独记录：加载时检测（`/\r\n/` 存在即 CRLF），状态栏展示；
- dirty 判定对 EOL 归一化后比较（`replace(/\r\n?/g, "\n")`），CRLF 文件加载即「已同步」；
- 保存时把编辑器文本按文件模式还原（CRLF → `\n` 全量替换为 `\r\n`）写盘，
  字节形态不漂移；外部变更检测同样按归一化比较，自写回声不会误报；
- 模块存档（state.json）只存语义内容（LF），EOL 归属于文件层面，二者解耦。

**边界**：混合换行文件按检测结果整体归一；孤立 `\r` 按 LF 处理；
编码栏显示 UTF-8 / UTF-8 BOM（后端以 UTF-8 严格读取）。

## 9. 停用语义修订：整块移除，存档即停用（ADR-004，修订 ADR-001）

**新模型**：停用模块时从文档中**整块移除**（不再留 `enabled="false"` 空壳），
正文写入存档；模块身份判定变为文件与存档互补——

| 文档中 | state.json | 语义 |
| --- | --- | --- |
| 有 | 无 | 启用 |
| 无 | 有 | 停用 |
| 有 | 有 | 启用（显示让位于文档，**存档保留**，见冲突策略） |
| 无 | 无 | 不存在 |

**采纳动机**：Agent 指令文件中不再有死标签噪音；外部工具（Agent 自身）抹掉模块
从「丢失」变为「自动转为停用、可恢复」——原孤儿存档问题（P2）由缺陷变为特性；
概念收敛（空壳、停用占位装饰、enabled="false" 生成全部移除）。

**必须配套的三件事**：

1. **存档可靠性前置（原 P0）**：存档成为停用集的唯一事实来源，state.json 写入
   改为临时文件原子替换，load 解析失败时先备份为 `state.json.bak` 再以空表继续，
   杜绝「损坏 → 静默清空」的雪崩路径。
2. **删除与停用的出口分离**：外部删除=停用（可恢复）；真删除走面板显式删除
   （清除存档条目）。停用区的删除按钮即此出口。
3. **位置锚**：停用时记录前驱模块名（`after`，身份锚比 index 稳），启用时优先
   插回锚模块之后、锚不存在则落文末。缓解停用导致分节顺序丢失的问题。

**配套策略**：启用即清除条目（存档条目仅存在于停用期间）。
**冲突策略（实测修订）**：「文档有同名启用模块 + 存档有条目」时**存档一律保留**，
显示层由面板过滤让位于文档。初版曾定为「以文档为准立即清除陈旧存档」，实测
暴露致命缺陷：停用后未保存就重启/切换文件，会精确制造这个组合——此时存档
承载的正是「尚未落盘的停用意图」，立即删档等于丢数据（已实际发生）。两类来源
（停用未落盘 vs 外部加回）无法区分，而误判代价不对称：多留一份存档无害，
误删不可逆。因此存档只在明确的用户动作中增删：删除模块、删除停用存档、
重命名迁移、启用恢复。`enabled="false"` 解析保持宽容（旧文件、手写壳可读，
启用时一并移除壳），生成端不再产出。存档键仍为 文件路径 + 模块名，跨文件互不共享。

## 10. 目标注册表与路径规则（源自 magpie 的 targetOf 清单）

注册表含 1 个共享目标 + 30 个 Agent 目标。共享目标使用 Pizzic 私有路径
`~/.pizzic/AGENTS.md`（早期为 `~/.agents/AGENTS.md`，迁移策略见第 11 节）。
路径规则采集自 magpie（`internal/library/targets.go` 的 targetOf 与各 agent 定义），
并做如下筛选：

- **收录**：用户级指令文件路径固定的 Agent（Claude Code、Codex、Gemini CLI、
  Antigravity、OpenCode、DevEco Code、MiMo Code、Pi、DSH、omp、OmO、Goose、
  Copilot CLI、Crush、ZCode、Kimi Code、Alma、Devin CLI、Grok Build、Droid、
  Qoder、Qoder CN、CodeBuddy Code、fx、Prime Agent、StepCode、jcode、AtomCode、
  Qwen Code、Reasonix）。
- **候选序列（firstThere）**：Agent 实际读取候选中第一个存在的文件（如 Devin
  `AGENTS.md → AGENT.md`、CodeBuddy `CODEBUDDY.md → CODEBUDDY.mdc`）。注册表
  每个目标持有候选数组：读取/监听/白名单覆盖全部候选，展示用第一个存在者。
  避免「Agent 读 A、我们写 B」的错位。
- **Override 即最高优先级候选**：codex/pi/omo/stepcode 支持 `AGENTS.override.md`
  （存在时 Agent 读它而非主文件）。它就是候选序列的第一项——存在时我们编辑的
  恰是 Agent 实际生效的文件，无需单独警示。与之配套，每个目标带 `create_rel`
  （主指令文件）：候选全不存在时按它新建（override 不会凭空创建）。
  Pi/OmO/Prime/StepCode 的 `AGENTS.MD`/`CLAUDE.MD` 大小写变体在 Windows 上
  与同名小写文件相同，折叠不列；`CLAUDE.md` 兜底候选保留。
- **排除**：Grok App（路径依赖 config.toml 解析，不固定）、WSL 变体（notify
  对 `\\wsl.localhost` UNC 路径不可靠）、插件 Agent（路径动态声明）、无用户级
  指令文件者（Cursor CLI、Zed、Cline 等）。
- 路径白名单（第 4 节）自动覆盖全部候选；监听目录（主目录 + 各候选父目录）
  覆盖全部候选所在目录，无需扩根。

## 11. 符号链接支持（ADR-005）

### 11.1 私有共享指令文件

共享目标从 `~/.agents/AGENTS.md` 迁到 `~/.pizzic/AGENTS.md`。旧路径可能被其他
工具以不同语义读取/写入，共用会造成内容冲突；私有路径让 Pizzic 成为唯一写入者。

启动时维护共享文件可用性（`shared::bootstrap`，不设迁移标记）：

| `.pizzic/AGENTS.md` | `.agents/AGENTS.md` | 行为 |
| --- | --- | --- |
| 被占用（文件或链接） | 任意 | 不动 |
| 缺失 | 是文件 | 复制内容；旧路径的停用存档并入新路径（同名以新路径为准，旧键保留）；弹框建议删除旧文件 |
| 缺失 | 不存在 | 创建空白共享文件 |

不设标记的理由：复制只在缺失时发生，删掉旧文件即切断复制来源，不会「删了又复活」。
复制失败不建空白文件（保留缺失态供下次启动重试），避免迁移被悄悄放弃。
迁移弹框的「保留旧文件」只是本次不再提示；删旧文件是危险动作（其他工具仍读它，
两处将不再同步），用危险色确认。

### 11.2 链接状态与只读语义

`TargetInfo` 增加 `isLink / linkTarget / linkTargetExists / linkTargetIsShared`。
`exists` 语义改为**路径被占用**（含悬空链接）：悬空链接是 Agent 指令文件的占位，
不能让候选序列越过它，也不能露出「创建文件」按钮（那会写穿链接目标）。
符号链接的判定使用 `symlink_metadata`（不跟随），内容可读性使用 `metadata`。

| 路径状态 | 编辑器 | 顶栏 | 侧栏 |
| --- | --- | --- | --- |
| 不存在 | 空态：创建文件 / 创建符号链接（仅 Agent） | — | 未创建 |
| 普通文件 | 可编辑 | — | 悬停：转链接、删除 |
| 链接 → 共享且有效 | 只读，显示共享内容 | 链接图标 + 目标路径 + 只读标签 | 薄荷链接标记 |
| 链接 → 共享但悬空 | 只读、空内容 | 同上（琥珀） | 琥珀断链标记 |
| 链接 → 其他（有效/悬空） | 只读、**不读取目标内容** | 同上（琥珀） | 琥珀链接/断链标记 |

只读实现为 CodeMirror `Compartment` 动态切换 `EditorState.readOnly` +
`EditorView.editable`；只读时隐藏保存按钮，`Ctrl+S` 仅提示。右侧面板保留模块
结构预览、全部写操作置灰，隐藏「已停用」区（存档属于该 Agent 自己的旧文件，
链接视图下展示会错位；数据仍保留）与共享模块库。

**为什么指向其他文件时不显示内容**：路径白名单的承诺是「Webview 无法借此读取
任意文件」。允许读外链会把任何一个可写注册表路径变成任意文件读取入口；
只读展示共享文件内容则没有这个缺口——共享文件本来就是 Pizzic 自己的目标。
指向其他目标的链接仍显示目标路径与警告，并提供「改指向共享指令」「删除链接」
两个就地出口。

### 11.3 创建、转换与改指向

`link_to_shared(path)` 一个命令覆盖三种入口，区别只在原文件处理：

- 普通文件 → 危险确认 → 原文件移入系统回收站（可还原）→ 建立链接；
- 链接指向别处 → 普通确认 → 改指向（链接不承载内容，无需回收，旧目标文件不受影响）；
- 路径不存在 → 直接建链接；已正确指向且可读 → 幂等返回。

若当前文件有未保存修改，前端先保存再调用，最新内容随原文件一起进回收站。
落盘顺序是「同目录建临时链接 → 处理原文件 → `rename` 就位」：创建链接的权限
问题会在触及原文件之前失败；原文件进回收站后可随时还原，最后的 `rename`
即使失败也不会造成不可逆的数据丢失。回收站取代了早期的应用内备份目录——
两者都是"可恢复的旧副本"，并存只会让用户困惑于哪一个才是权威副本。

权限不足（Windows 错误 1314）提示开启开发者模式或提权运行，**不做复制降级**：
静默复制会让用户误以为链接仍然同步。

删除（侧栏悬停）只删路径本身，且一律**移入系统回收站**（可还原），不做永久
删除：链接只回收链接本身（`trash` 只规范化父目录，不跟随链接目标），普通文件
需确认；停用存档保留，从回收站还原文件后可继续恢复。悬空链接可能无法被 Shell
解析、进不了回收站，仅这一种情形退回直接删除链接（不承载内容，且是修复坏
链接的必要出口）。共享目标只有在自身是符号链接时才可删除（保护共享正文，
同时给异常状态留修复出口）。不提供「链接转回普通文件」：需要时删除链接后在
空态重建即可。

### 11.4 外部变化

共享文件被外部修改时，指向它的链接视图自动静默重载（只读没有未保存内容可丢）。
当前文件在外部被换成符号链接且本地有未保存修改时，保留缓冲区但禁用保存，
横幅只提供「放弃本地修改并重新加载」。
